# 项目演示稿（PROJECT_PRESENTATION）

> 面向校招技术面 / 项目介绍场景，10-15 分钟叙述框架。所有数字来自仓库内 golden 存档与测试报告，无虚构。

## 一句话介绍

一个**生产级企业知识库问答系统**：FastAPI + PostgreSQL/pgvector + LangChain，蓝绿索引零停机重建，混合检索 + 交叉编码器精排，SSE 流式输出，64 项自动化测试 + 故障注入 + 并发压测全部真实执行。

## 架构（讲解顺序）

```
用户 → FastAPI（限流/认证/结构化日志）
     ├─ 查询路由：规则特征 → 证据校验(阈值0.25实验校准) → LLM 兜底
     ├─ 检索链路：BGE-M3(1024维) + BM25(jieba) → RRF(60) → CrossEncoder → 父块展开
     ├─ 生成：DeepSeek（SSE 逐 token）+ 来源编号引用
     └─ 存储：PostgreSQL + pgvector
         ├─ 蓝绿索引：building → 校验 → 原子切换 is_active → retired 保留
         ├─ 三层并发：进程锁 + advisory lock + 任务表（409 冲突）
         └─ 心跳恢复：stale_seconds=300，活跃构建不被误杀
```

## 三个最值得讲的技术点

### 1. 蓝绿索引与故障注入（可靠性）

- 问题：传统 RAG 重建"先删后建"，中途失败 = 索引损坏且不可恢复
- 方案：行级版本 + `WHERE is_active` 部分唯一索引；构建-校验-切换三阶段；10+2 项故障注入（PDF 失败降级、嵌入全挂拒空版本、切换前后崩溃、写失败回滚）
- 数据：压测中重建期间 **180 次并发读取 0 失败**；重复重建零重复记录

### 2. 存储选型的实证决策（判断力）

- langchain-postgres PGVectorStore 六项实证否决（langchain-core≥1.2 依赖冲突、async-first 在 Windows 抛错、sync 工厂路径损坏、单表无外键、事务不可统一、UUID 强制）
- 自研 SQLAlchemy 适配层约 400 行，30 项集成测试覆盖
- 讲述要点：**用数据与原型说话，而不是社区热度**

### 3. 把"评测"当产品能力（工程素养）

- 检索指标（HitRate/MRR/NDCG）四端点对比、路由 48 用例评测、rerank 阈值分布实验校准（0.45→0.25）、迁移前后零回退门禁
- 修复过的真实缺陷都有测试固化（jsonb 契约、空版本、init 竞态、恢复误杀）
