# 性能报告（V2）

所有数据为真实运行测量（2026-11-15），环境：Windows 11 / Docker Desktop / PostgreSQL 16 容器 / CPU 推理（无 GPU）。 golden 存档：`tests/golden/`（retrieval_metrics.json、rerank_calibration.json、stress_perf.json）。

## 1. 检索端点质量与延迟（13 用例，TestClient 进程内）

| 端点 | HitRate | MRR | NDCG@5 | 平均延迟 |
| --- | --- | --- | --- | --- |
| /search（向量） | 100% | 0.962 | 0.959 | 506ms |
| /keyword-search（BM25） | 100% | 0.733 | 0.813 | 127ms |
| /hybrid-search（RRF） | 100% | 0.962 | 0.931 | 326ms |
| /rerank-search（精排） | 100% | 0.962 | **0.963** | 9441ms（首调含模型加载，稳态 ~3s/查询见容器日志） |

结论：rerank 排序质量最高（NDCG），代价是延迟；BM25 最快但排序最弱——混合链路的分工与实测一致。

## 2. Rerank 阈值校准（真实模型 + 真实语料）

| 分布 | n | mean | min/max |
| --- | --- | --- | --- |
| 正样本（10 个在题查询）top-1 分数 | 10 | 0.914 | min 0.462 |
| 负样本（8 个离题查询）top-1 分数 | 8 | 0.012 | max 0.082 |

阈值扫描确定 **0.25** 为操作点（recall 100%、FPR 0%，两侧等边距：距最强负样本 0.17、距最弱正样本 0.21）。旧值 0.45 距最弱正样本仅 0.012——边界查询易翻转。已在 evidence_checker 生效并回归验证。

## 3. 并发压测（对运行中容器，修复后）

| 探针 | 结果 |
| --- | --- |
| 并发检索：20 请求 / 8 并发 | **0 错误**；p50=1559ms、p95=20246ms（单次长尾，容器 CPU 嵌入批处理抖动） |
| 并发重建（2 同时发起） | 状态 [200, 200]——RLock + 任务守卫正确**串行化**，任一时刻仅一个构建 |
| 重建期间并发读取 | **180 次读取 0 失败**——蓝绿切换期间读服务不间断 |
| 嵌入吞吐（宿主机） | 模型加载 3.6s（缓存）；139 文本 63.7s → **2.2 texts/s**（CPU ONNX） |

**修复前对照**（V2 修复前首次压测，同一容器）：并发首请求触发 RagService 竞态初始化 → 连接池超时（`ConnectionTimeout`，见 api 日志 19:43）；恢复机制误杀活跃构建（任务 23 "Cannot activate version in status=failed"）。两项均已修复（双检锁 + 任务心跳），修复后压测零错误。

## 4. 模型加载与预热

| 模型 | 冷加载 | 缓存后 |
| --- | --- | --- |
| BGE-M3 ONNX | ~20-30s | 3.6s |
| bge-reranker-base（torch） | ~35-40s | <2s |

缓解：RagService 启动后台线程预热 rerank；容器 healthcheck start_period 120s 吸收冷启动。已观测的残留风险：宿主机内存紧张时 CrossEncoder 偶发 meta-tensor 加载失败（ SSE 测试中发现，重试即恢复）——生产建议限制并发构建或使用独立推理进程。

## 5. 全量重建耗时分解（139 子块 / 7 文件）

- 嵌入（宿主机 CPU）：~64s（瓶颈，2.2 texts/s）
- DB 写入（417 行父子块级联）：毫秒级/文件
- 校验+激活：毫秒级
- 容器内重建：~2-4 分钟（容器 CPU 较宿主机慢 + 模型冷加载）

## 6. 遗留性能事项

- p95 长尾（20s）：容器内 onnxruntime 批处理偶发抖动，量级不影响单用户；并发扩容前建议加请求级超时（v2.1）
- `/chat` 全链路（含 LLM）延迟由 DeepSeek 服务主导（60-120s 超时预算）
- BM25 全内存语料：当前 139 块毫秒级；语料增长后需评估迁移 PG tsvector
