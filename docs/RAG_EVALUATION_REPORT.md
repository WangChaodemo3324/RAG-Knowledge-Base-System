评测集：V3.5 扩充至 **12 用例 × 4 类别**（精确/跨段落/多文档/无答案），四端点真实检索。golden 存档：`tests/golden/retrieval_metrics.json`、`rerank_calibration.json`。

**解读**：V3.5 引入更难的类别后，全局 HitRate 从 100%（V2 简单集）降至 75%——**下降全部来自"无答案"类**（检索端点按设计返回候选，无拒答语义），有答案类（精确+跨段落+多文档）在 rerank 端点全部命中。这不是质量退化，是评测集变难了。

| 类别 | 结果 | 说明 |

## 3. 无答案场景的正确度量（重要澄清）

检索端点（/search 等）的语义是"返回最相关候选"，永远有输出——**拒答决策属于问答链路**：

- 离题查询的 top-1 rerank 分数实测 **max 0.082**（rerank_calibration，8 负样本）
- 校准阈值 0.25 → evidence_checker 判"证据不足" → 路由层拒绝编造（KB_THEN_WEB / NO_EVIDENCE）
- 因此无答案场景的**正确验收位置是问答链路**：已由校准实验 + 路由评测（48/48 含私有问题拒编造）覆盖

**结论**：检索层无缺陷；"无答案拒答"由链路层保证，链路级 Faithfulness 评估见 §5。

## 4. 与 V2 基线对比（回归）

13 用例原集保留于 `baseline_retrieval.json` 与 `pgvector_v2_retrieval.json`——迁移前后零回退的结论维持有效。V3.5 扩充集不替换原基线，二者互补（原集=回归门禁，扩充集=能力边界探测）。

## 5. 生成层评估（Faithfulness / Answer Relevance）

- 属生成层指标，需真实 LLM 逐条判定（付费 API 批量实验被任务禁止）
- **已执行的冒烟证据**：真实 DeepSeek SSE 冒烟（567 tokens）——回答含来源编号引用、结论与引用文档内容一致（人工比对 883 字符回答与 [1] 来源内容）
- **预留路径**：`tools/eval_retrieval.py` 的框架可直接扩展 faithfulness 判分函数（LLM as judge），建议 v2.1 以 10-20 条样本小批量运行
- **链路级防幻觉机制**（代码实证）：rerank 阈值拒答 + 私有内部问题禁公网补料 + 提示词强制编号引用 + 历史对话不作事实来源

## 6. 结论

- 检索质量：有答案场景全命中，rerank 排序价值经 NDCG 实证
- 无答案防护：链路层机制齐备且有实验数据
- 全部优化均有实验依据：阈值 0.25（分布实验）、路由 48/48（规则调优前后对比）、V2 各项修复有回归门禁
